2. Estratégia da GameSim

C# puro em assembly separado, sem referência a UnityEngine:

  • RagnaTale.Sim (.NET Standard 2.1, compilável por dotnet e pela Unity via asmdef/DLL): Sim, regras, dados, protocolo de rede, persistência pura.
  • RagnaTale.Sim.Tests (NUnit) roda em dotnet test (CI, servidor headless, sem Editor) e no Test Runner da Unity.
  • Servidor autoritativo = processo .NET que referencia o mesmo assembly: mantém a ADR-0001 (cliente só vê snapshots) e não exige Editor.
  • Contrato mantido: RequestXxx(...) na Sim; entrada e IA só pedem; apresentação reage a eventos C#. NetGateway vira INetGateway com allowlist de pedidos (ADR-0008), implementação local primeiro.
  • Cuidados de paridade: RNG próprio com semente explícita (nunca System.Random/UnityEngine.Random); ordem de iteração de dicionários controlada onde afetar resultado; mesmo float IEEE.

Dados: JSON canônico, não ScriptableObject. Motivo: servidor headless e testes dotnet não carregam SO; ids estáveis por nome de arquivo (ADR-0004) já são chaves de JSON; diffs legíveis; o pipeline Python do Codex lê JSON mais fácil que .tres. SO fica só como camada opcional de editor (importador JSON->SO para prefabs referenciados por id), nunca lida pela Sim. Passo: tools/migrate/tres_to_json.py exporta os 302 .tres; teste de paridade compara campo a campo com o DataDB do Godot.

Preservar os ~14,5 mil checks:

  1. Com o Godot ainda funcionando, gravar um golden (tests/golden/*.json): cenários determinísticos (sementes fixas, sequências de pedidos) com estados, eventos e saídas de fórmulas.
  2. Portar run_unit_tests.gd por sistema para NUnit (mecânico: check(a==b) -> Assert), mantendo nomes; tabela GDScript x C# de contagem até zerar a diferença.
  3. Testes de paridade leem o golden e exigem igualdade (tolerância 1e-4 só onde há float acumulado).
  4. Godot só é desligado com contagem C# >= GDScript e golden verde.

4. Riscos e o que NÃO migra

Não migra: arte 2D e conceitos, documentos de design, site/Pages, Codex, EAP, scripts Python, Blender, Customuse/Meshy (saídas entram como glTF/FBX; rig e texturas revalidados no Unity).

Riscos:

  1. Paridade numérica (ordem de dicionário, RNG, float): golden + RNG próprio.
  2. M2 maior que o estimado (3,9 mil linhas de teste, 42 arquivos de sim): portar por sistema, contagem rastreada.
  3. Sem equivalente direto: .tres com sub-resources aninhados, sinais, NavigationServer, .gdshader (reescrita manual).
  4. Rig e animação do herói: reimportar, revisar retarget e root motion.
  5. Câmera e picking: refazer a calibragem com a spec.
  6. Unity MCP é pacote de terceiros: aval do technical-director e versão fixada.
  7. Persistência e telemetria (ADR-0002/0007) usam FileAccess do Godot: abstrair em interface.
  8. Dois motores em paralelo dividem o foco: Godot só em manutenção.
  9. Docs ainda dizem Godot (CLAUDE.md, ADRs 0001-0008, STATUS, control-manifest, engine-reference): atualizar conforme o ADR de troca.
