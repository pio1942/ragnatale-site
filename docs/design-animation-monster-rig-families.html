Famílias de rig de monstros (molde: goblin raider)

Status: rascunho v1 (2026-11-11). Dono: game-designer. Decisão do criador (2026-11-11): monstros agrupam-se por família de esqueleto; conjunto-base compartilhado + 2-3 clipes-assinatura por monstro + variação de escala/ritmo. Fontes: data/enemies/*.tres (51 fichas; race, size, archetype, rank), design/gdd/monsters.md (3.3, 3.6), design/animation/motion-catalog.md (fases e janelas), unity/Assets/Editor/GoblinAnimationBuilder.cs, GoblinAnimationTests.cs, sim/RagnaTale.Sim.Tests/ActionContractTests.cs. Método: classificação por race + size + archetype + id/nome. Não conferi os conceitos de arte (assets/concepts/); onde o corpo é ambíguo está marcado "?" e vale revisar antes de modelar.

0. Molde existente (goblin raider)

Avatar Humanoid (FBX v2.2) + clipes do UAL (Quaternius, UAL1_Standard) retargetados. Controller Goblin.controller: parâmetros Speed (float), Attack/Hit (trigger), Dead (bool); estados Locomotion (blend Idle 0 / Walk 1,8 / Jog 4,2), Attack, Hit, Death; Attack e Hit vêm de Any State. applyRootMotion = false. Ficha: attack_windup 0,45 s, attack_interval 1,5 s (logo Impacto em 0,45 s e recuperação ~1,05 s); MIN_TELEGRAPH = 0,30 s (monsters.md 3.5).

2. Conjunto-base e clipes-assinatura

Fases: Preparo = Windup (início do clipe até o evento Impact), Impacto = evento de 1 quadro (+ pausa), Recuperação = Impact até End. O clipe nunca decide dano; o servidor define ImpactTick/RecoveryEndTick e o clipe é escalado por speed para casar (regra de motion-catalog.md 2). Preparo mínimo 0,30 s (MIN_TELEGRAPH); chefes maior (MIN_BOSS_TELEGRAPH). Cancelled corta o clipe com blend de 0,1 s.

4. Esquema de dados proposto

Hierarquia: família (rig + controller base) -> override por monstro (clipes-assinatura, escala, ritmo). Chaves id estáveis como em data/enemies.

``` data/json/anim/rig_families.json { "humanoid_small": { "rig": "Humanoid", "avatar": "HumanoidSmall", "base_controller": "Anim/Families/HumanoidSmall.controller", "base_clips": { "idle": "...", "walk": "...", "run": "...", "attack": "...", "hit": "...", "death": "...", "spawn": "...", "aggro": "..." }, "params": ["Speed","Attack","Hit","Dead","Spawn","Aggro"], "locomotion_blend": [0, 1.8, 4.2] }, ... }

data/json/anim/monster_anim.json { "goblin_raider": { "family": "humanoid_small" }, "goblin_raider_veteran": { "family": "humanoid_small", "scale": 1.1, "speed_mul": 0.95 }, "goblin_lookout": { "family": "humanoid_small", "signature": ["whistle", "point"] } } ```

Campos de override: family (obrigatório), scale, speed_mul (ritmo; não altera janelas do servidor), signature[] (até 3 ids de clipe que entram via AnimatorOverrideController), attack_clip_override, tint (já existe em dados de arte). Janelas (windup/impact/recovery) vêm da ficha do monstro (attack_windup, attack_interval, habilidades), não do JSON de animação: o builder calcula speed = clipPreparo / windup e posiciona o evento Impact.

Pipeline Unity: um builder por família (HumanoidSmallAnimationBuilder generaliza o GoblinAnimationBuilder) gera Families/<fam>.controller; por monstro gera AnimatorOverrideController com os clipes-assinatura; teste EditMode por família (como GoblinAnimationTests: avatar, clipes presentes, parâmetros, transições, evento Impact em cada ataque).
