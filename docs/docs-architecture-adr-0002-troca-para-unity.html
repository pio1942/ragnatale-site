ADR-0009: Troca de motor Godot 4.7.2 -> Unity 6 (URP, C#)

Nome do arquivo pedido pelo criador (adr-0002-troca-para-unity.md); o número 0002 já é de persistência, então o id lógico é ADR-0009.

Summary

O projeto, com 3 dias de vida, troca de Godot (GDScript) para Unity 6 com URP e C#. A GameSim vira C# puro em assembly sem UnityEngine (servidor .NET headless), dados em JSON canônico, ~14,5 mil checks portados com golden de paridade; Godot fica em manutenção até a paridade da Sim.

Context

Problem Statement

Escolher o motor definitivo antes que o custo de migração cresça.

Current State

Godot 4.7.2/GDScript: 42 arquivos de sim, 302 .tres, ~14,5 mil checks.

Constraints

Manter ADR-0001; não perder a cobertura de testes; sem gasto pago sem "sim" do criador.

Requirements

Sim determinística e testável fora do Editor; servidor headless; arte/docs/Codex preservados.

Decision

Migrar para Unity 6 (URP, C#) conforme docs/architecture/unity-migration-plan.md: assembly RagnaTale.Sim (.NET Standard 2.1) sem UnityEngine; servidor .NET headless referenciando o mesmo assembly; dados em JSON canônico (ScriptableObject só como camada opcional de editor); UI Toolkit; rede sobre protocolo próprio com UTP ou LiteNetLib (NGO como plano B); marcos M0-M5; pasta unity/ neste repositório. Itens do plano ainda em aberto (versão exata, aval do Unity MCP de terceiros, escolha final de transporte, Git LFS) seguem como pendências do criador na seção 5 do plano.

Implementation Guidelines

  • Must: RNG próprio com semente explícita; Request* na Sim, apresentação reage a eventos.
  • Must never: referenciar UnityEngine em RagnaTale.Sim; desligar o Godot antes de checks C# >= GDScript e golden verde.

Alternatives Considered

Alternative 1: Permanecer em Godot

  • Pros: sem custo de migração, 14,5 mil checks já verdes.
  • Cons: decisão do criador por Unity.
  • Rejection Reason: escolha do criador.

Alternative 2: Netcode for GameObjects

  • Pros: velocidade de protótipo.
  • Cons: replicação de objetos compete com a autoridade projetada; exige Unity no servidor.
  • Rejection Reason: plano B apenas.

Consequences

Positive

Sim testável com dotnet test, servidor sem Editor, ecossistema Unity.

Negative

Reescrita de atores, câmera, visual, UI e shaders (~3 a 4 semanas estimadas); dois motores em paralelo até a paridade.

Neutral

Arte, Blender, Codex, site, docs e EAP independem do motor.

Risks

Ver plano seção 4 (paridade numérica, M2 maior que o estimado, rig/retarget, Unity MCP de terceiros). Mitigação: golden, RNG próprio, portar por sistema.

GDD Requirements Addressed

Foundational — no GDD requirement. Constrains: camera-system (spec FOV 22, pitch 50, yaw 45), todos os GDDs de sim (paridade numérica).

Performance Implications

  • CPU: tick igual ou melhor que o baseline atual (critério do M2).
  • Memory: a medir.
  • Load Time: a medir.
  • Network: protocolo próprio mantido.

Migration Plan

Marcos M0-M5 em docs/architecture/unity-migration-plan.md.

Rollback plan: Godot permanece intacto e em manutenção até a paridade; reverter = continuar nele.

Validation Criteria

Checks C# >= ~14,5 mil, golden verde, 16 prints do emblem-map reproduzidos (M3), dois clientes sincronizados com soak de 5 min (M5).
