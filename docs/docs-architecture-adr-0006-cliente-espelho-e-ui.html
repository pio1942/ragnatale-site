ADR-0006: Cliente espelho (ClientWorld), UI e camada de apresentação

Status

Accepted (2026-11-08) — confirmação explícita do criador, dada por ele mesmo no chat: "1 - aprovado", em resposta ao pedido "aceito as ADRs 0002 a 0008".

Date

2026-11-07

Last Verified

2026-11-07 (contra ADR-0001 2.3/2.5/3.3 e docs/engine-reference/godot/modules/ui.md; a seção "UI (4.6)" e "UI and Input (4.7)" de current-best-practices.md deve ser relida antes de codificar)

Decision Makers

technical-director (proposta), ui-programmer, ux-designer

Summary

O ADR-0001 manda a apresentação ler um espelho de estado, mas não define o contrato do ClientWorld, o fluxo de eventos para a interface nem as regras de UI. Proposta: ClientWorld com a mesma assinatura de leitura da GameSim, eventos tipados e UI que nunca escreve estado.

Context

Problem Statement

HUD e visual hoje chamam sim.get_entity etc. (ADR-0001 3.3). Falta definir o espelho, a interpolação, o tratamento de latência na UI (comando enviado, Ack pendente) e como o cliente apresenta dados privados e de grupo.

Requirements

Decorrentes de TR-resources-001 (estado privado ao dono), TR-party-005, TR-anticheat-001 (cliente sem autoridade).

Decision

  1. ClientWorld expõe as mesmas leituras que a GameSim (get_entity, cooldown_remaining, move_speed_of...) lendo snapshots interpolados (atraso 100 ms) e estado privado; é a única fonte para HUD e visual.
  2. Mudanças chegam por sinais tipados (damage_dealt, gold_changed...), um por tipo de Event do protocolo; UI conecta por Callable tipado, sem strings.
  3. scripts/ui/ e scripts/visual/ não importam scripts/sim/ nem scripts/net/, só ClientWorld; a interface envia intenções por um CommandSender, nunca chama request_*.
  4. Cliques do mundo somente em _unhandled_input (regra já vigente).
  5. Estados pendentes: botão mostra "enviado" até o Ack; falha do servidor reverte a animação.
  6. Todo texto em português do Brasil; tabelas de texto em arquivo, prontas para localização.
  7. Acessibilidade seguirá design/accessibility-requirements.md (a criar).

Consequences

Positivas: troca mínima de código (sim vira world), testável sem rede com ClientWorld falso. Negativas: dois lados (GameSim e ClientWorld) devem manter assinatura compatível; testes de contrato necessários.

Performance Implications

  • Meta de cliente: 60 FPS, quadro de 16,6 ms, 1000 chamadas de desenho (project.yaml), 2048 MB.
  • Atualizar o espelho no máximo uma vez por snapshot; HUD atualiza por sinal, não por _process.

Validation Criteria

  • Teste de contrato: toda leitura usada pela UI existe no ClientWorld.
  • Análise estática (grep) garante que scripts/ui/ e scripts/visual/ não referenciam scripts/sim/.
  • Capturas de tela retidas em production/qa/evidence/ para cada tela tocada.
